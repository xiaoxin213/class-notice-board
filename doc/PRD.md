# 班级通知屏 — 产品需求文档（现状梳理版）

> **来源说明**：本文档依据 3 张来自小红书的参考产品截图逆向梳理，属于**同类产品拆解**，不是我们已有的产品。我们要做的是面向同一场景的自研版本，功能取舍可以不跟它一致。标注 `【待确认】` 的是截图中未体现或看不清、需要自行定义的部分。
>
> 需求来源：家属（一线老师）看到该产品后提出的实际使用需求。
>
> 版本：v0.1 现状梳理　　整理日期：2026-09-07

## 1. 产品定位

面向中小学班主任的**班级通知快速下发工具**。

老师在手机或个人电脑上通过 Web 页面发布通知，安装在教室电脑上的客户端会**同步全屏显示通知内容并语音播报**，替代原本"跑到教室喊一嗓子"或"发微信群但学生看不到"的场景。

**核心价值主张（登录页三个卖点）**

| 卖点 | 说明 |
| --- | --- |
| 一键发布 | 快速发送班级通知 |
| 语音播报 | 支持朗读自动播报 |
| 安全可靠 | 教室端可靠接收 |

## 2. 角色与权限

| 角色 | 载体 | 权限 |
| --- | --- | --- |
| 老师（班主任 / 兼任教师） | Web 页面（手机 + 电脑） | 注册登录、管理班级、发布通知、绑定教室端、查看在线状态与发布记录 |
| 教室端 | 教室电脑客户端 | **无需登录**，通过绑定代码与班级关联，只接收和展示，不发布 |

登录页明确标注：**仅老师账号可发布通知，教室屏无需登录。**

这是一个关键设计——教室电脑是公共设备，不应该持有老师账号凭据。

## 3. 功能清单

### 3.1 账号体系（截图 1）

- 登录 / 注册 双 Tab 切换
- 登录字段：账号名（如 `chenfeifei`）、密码
- 注册入口文案："没有账号？使用邀请码注册" → **注册需要邀请码**，非开放注册，说明当前走的是学校/渠道邀请制
- "忘记密码" 入口
- 登录页左侧有教室屏效果预览卡片（静态演示：三年二班 / 已连接 / 语音已开启 / "请全班同学马上到操场集合。" / 王老师 发布 16:42 / 教室端已收到通知）

### 3.2 班级列表（截图 2、3 左栏）

- 顶部显示配额：`5/50 个班级`，即**单账号最多 50 个班级**
- `+` 新增班级
- 列表项包含：班级名称、在线/离线状态点、角色标签（截图中可见"兼任"等文案，具体枚举【待确认】）
- 截图中的班级：三年一班、三年二班、办公室、五(1)班（在线）、五(2)班
- **"办公室" 也是一个班级项** → 说明"班级"本质是**接收终端分组**，不限于教学班，办公室、功能室同样可作为接收对象
- 选中某个班级后，右侧的教室绑定区域跟随切换

### 3.3 发布通知（截图 2、3 中栏）

区域说明文案：选择班级、输入内容，通知会同步显示到教室电脑。

| 字段 | 规则 |
| --- | --- |
| 接收班级 | 下拉单选，默认当前选中班级（截图为"五(1)班"）。是否支持多班群发【待确认】 |
| 通知内容 | 多行文本，**上限 200 字**，实时显示计数（截图为 21/200） |
| 大屏显示时间 | 单选：30秒 / 1分钟（默认选中）/ 5分钟 / 自定义 |
| 语音播报次数 | 单选：1次 / 2次（默认选中）/ 自定义 |

**常用模板**（一键填充通知内容）：请到办公室、到操场集合、带作业本来办公室、课代表来办公室

**操作按钮**：

- `立即发布` — 主按钮
- `预览大屏` — 发布前在本地预览教室屏的实际呈现效果

### 3.4 教室绑定（截图 2、3 右栏）

这是整套产品的连接枢纽：

- `生成` 按钮 — 生成绑定代码
- 当前班级：五(1)班
- **绑定代码：6 位数字**（截图为 `832813`），带一键复制
- **有效期**：截图显示 `2026-07-05 16:58:33 后过期`，即绑定代码是**有时效的一次性凭据**
- 状态标识：`教室端在线`
- `复制链接` — 推测用于把教室端下载/接入地址发给他人【待确认】
- `声音测试` — 远程触发教室端播放测试音，用来确认教室电脑音箱开着、音量正常

> 教室端的接入流程应为：教室电脑启动客户端 → 老师在 Web 端为某班级生成 6 位绑定代码 → 在教室电脑上输入该代码 → 完成绑定，此后长期有效。**具体输入方向（是在教室端输码，还是教室端出码、老师在 Web 输码）需确认**——从"复制链接/复制代码"的交互看，更像是老师侧生成、教室侧输入。

### 3.5 在线状态（截图 2、3 右下）

- 按班级列出终端在线台数：三年二班 0台在线 / 办公室 0台在线 / 五(1)班 1台在线 / 五(2)班 0台在线
- `刷新` 手动刷新
- **单班级可绑定多台设备**（文案是"台"），支持一间教室多屏或一个班级跨教室

### 3.6 发布记录（截图 2、3 中栏底部）

- 展示历史发布，截图显示"最近 1 条"
- 字段与是否支持重发/撤回【待确认】

### 3.7 全局状态（截图 2、3 顶栏）

- `服务已连接` — Web 端与服务器的长连接状态指示
- 当前账号 `chenfeifei` + 下拉菜单
- `退出登录`

## 4. 教室端展示形态（截图 1 预览卡片）

- 顶部信息条：班级名 + `已连接` + `语音已开启`
- 主体：**超大字号居中显示通知正文**（教室后排也要看得清，这是排版第一原则）
- 底部信息条：发布人（王老师 发布）+ 发布时间（16:42）+ 回执状态（教室端已收到通知）
- 到达设定的显示时长后自动收起，回到待机态【待确认待机态长什么样】

## 5. 关键业务规则汇总

1. 通知正文 ≤ 200 字
2. 单账号 ≤ 50 个班级
3. 绑定代码 6 位数字、带过期时间
4. 显示时长与播报次数均为发布时逐条设置，非全局配置
5. 教室端零登录、零账号
6. 注册需邀请码

## 6. 待确认清单

- [ ] 班级列表右侧角色标签的完整枚举（班主任 / 兼任 / ？）
- [ ] 是否支持一次发布到多个班级（全校群发场景）
- [ ] "复制链接" 的确切用途
- [ ] 教室端离线时发布的通知，上线后是否补发、补发是否补播语音
- [ ] 语音播报是教室端本地 TTS 还是服务端合成后下发音频
- [ ] 发布记录的保留时长、是否支持撤回
- [ ] 是否有学校/年级管理员角色（跨班级、跨教师的管理层）
- [ ] 教师账号与班级的归属关系：一个班级能否被多个老师发布（截图有"兼任"标签，暗示可以）
