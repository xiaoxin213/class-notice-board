# 部署说明

> 面向 VPS 运维。目标是**并入已有的 Docker 环境**，不额外引入数据库容器、不额外引入 nginx 容器。

---

## 1. 资源占用

服务端是**单容器、单进程、零外部依赖**，前端静态文件由服务端内建的文件服务托管，无需额外 nginx 容器：

| 项 | 实测 / 预估 |
| --- | --- |
| 常驻内存 | 空载约 76 MB（已限制 V8 堆上限 128 MB） |
| 镜像大小 | 约 180 MB（node:22-alpine + 前端构建产物） |
| 磁盘 | 初始约 140 KB，一所学校一学年的通知记录预计 < 50 MB |
| CPU | 空闲接近 0；瓶颈是长连接数而非算力 |

compose 里已设 `mem_limit: 192m` / `cpus: 0.5`，跑在 1C1G 的小机器上也留得下余量。

**为什么用 SQLite（`node:sqlite`）不用 PostgreSQL**：这个场景的写入量极低（一所学校一天几十条通知），读取几乎都是按班级取最近 30 条。单独跑一个 PG 容器要多吃 100~150 MB 内存和一份运维成本，收益是零。SQLite 是单文件，备份就是复制文件。真到需要多实例的那天再迁，SQL 基本不用改。

**没有 Redis**：设备在线状态只放进程内存，重启后教室端会自动重连恢复，不需要外部状态存储。

## 2. 镜像来源（GHCR）

镜像由 GitHub Actions 在每次 `main` 分支推送后自动构建并推送到 GitHub Container Registry：

```
ghcr.io/xiaoxin213/class-notice-board:latest
```

镜像是多阶段构建：
- **stage 1**：`npm run build` 编译 React 前端
- **stage 2**：安装服务端生产依赖
- **stage 3**：运行时，服务端 + 前端静态文件一体

前端静态文件打包进镜像，由服务端 `/app/web` 目录托管，通过 `WEB_ROOT` 环境变量激活。

## 3. 并入已有 compose（推荐）

把以下 service 片段加入你的 `01-docker/docker-compose.yml`：

```yaml
class-notice-board:
  image: ghcr.io/xiaoxin213/class-notice-board:latest
  container_name: class-notice-board
  restart: unless-stopped
  environment:
    TOKEN_SECRET: ${CNB_TOKEN_SECRET:?}
    INVITE_CODE:  ${CNB_INVITE_CODE:-}
    LOG_LEVEL:    ${CNB_LOG_LEVEL:-info}
  volumes:
    - ./data/class-notice-board:/data
  networks:
    peterxin:
      ipv4_address: 192.168.10.31
  mem_limit: 192m
  cpus: 0.5
  logging:
    driver: json-file
    options: { max-size: "10m", max-file: "3" }
```

在 VPS 的 `/root/peterdocker/` 目录下创建 `.env`（或追加到已有 `.env`）：

```bash
# 生成密钥
openssl rand -hex 32

CNB_TOKEN_SECRET=<上面生成的字符串>
CNB_INVITE_CODE=SCHOOL2026
CNB_LOG_LEVEL=info
```

## 4. 反向代理配置（nginx）

**这一段是最容易出问题的地方**，两个坑：WebSocket 需要 Upgrade 头透传，SSE 需要关闭缓冲。

服务端已在 SSE 响应里加了 `X-Accel-Buffering: no`，nginx 会自动关缓冲，无需在 conf 里单独设置。

```nginx
server {
  listen 80;
  listen 7443 ssl;
  listen [::]:7443 ssl;
  http2 on;
  server_name your-domain.com;   # 改成你的域名

  ssl_certificate     /etc/nginx/cert/your-domain.com_ecc/fullchain.cer;
  ssl_certificate_key /etc/nginx/cert/your-domain.com_ecc/your-domain.com.key;
  ssl_protocols TLSv1.2 TLSv1.3;
  ssl_session_cache shared:SSL:10m;
  ssl_session_timeout 10m;
  add_header Strict-Transport-Security "max-age=31536000";

  location ~ ^/\.well-known {
    proxy_pass http://192.168.10.5:80;   # acme.sh
    proxy_set_header Host $host;
  }

  location / {
    proxy_pass http://192.168.10.31:3210;
    proxy_http_version 1.1;

    # WebSocket 升级（教室端长连接）
    proxy_set_header Upgrade    $http_upgrade;
    proxy_set_header Connection "upgrade";

    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # SSE 长连接超时
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
  }
}
```

### 必须上 HTTPS

教室端走 `wss://`，教师端在手机上用。域名要**固定、单一、已备案**——学校网络做域名白名单时，IT 老师只需要放行一个域名。

## 5. 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TOKEN_SECRET` | 随机 | **生产必填**。不设置则每次重启后所有人被登出 |
| `INVITE_CODE` | 空 | 注册邀请码。**留空等于开放注册**，公网部署务必设置 |
| `WEB_ROOT` | `/app/web` | 前端静态文件目录，Dockerfile 已内置，通常不需要改 |
| `PORT` / `HOST` | 3210 / 0.0.0.0 | 监听地址 |
| `DATA_DIR` | /data | SQLite 数据目录，必须挂持久卷 |
| `TOKEN_TTL_SECONDS` | 2592000 | 登录态有效期，默认 30 天 |
| `BIND_CODE_TTL_SECONDS` | 1800 | 绑定码有效期，默认 30 分钟 |
| `NOTICE_TTL_SECONDS` | 300 | 通知存活时间，超时不再补投 |
| `MAX_CLASSES` | 50 | 单账号班级数上限 |
| `MAX_NOTICE_LENGTH` | 200 | 通知正文字数上限 |
| `HEARTBEAT_INTERVAL_MS` | 25000 | 心跳间隔 |
| `OFFLINE_TIMEOUT_MS` | 60000 | 超过该时间无心跳判离线 |

## 6. 备份

SQLite 使用 WAL 模式，不能直接 `cp`，使用 `VACUUM INTO` 做一致性备份：

```bash
# 在容器内执行一致性备份
docker compose exec class-notice-board \
  node --input-type=module -e "
import { DatabaseSync } from 'node:sqlite';
const db = new DatabaseSync('/data/data.db');
db.exec(\"VACUUM INTO '/data/backup.db'\");
db.close();
console.log('backup ok');
"

# 把备份文件复制到宿主机
docker compose cp class-notice-board:/data/backup.db ./backup-$(date +%F).db
```

数据量很小，加进你现有的定时备份即可。

## 7. 升级

```bash
# GHCR 镜像方式（生产环境推荐）
docker compose pull class-notice-board
docker compose up -d class-notice-board

# 本地构建方式（开发调试）
git pull
docker compose up -d --build
```

数据库表结构用 `CREATE TABLE IF NOT EXISTS` 幂等创建，重启不会丢数据。**将来涉及改表结构时需要写迁移脚本**，目前还没有。

## 8. 排查

| 现象 | 排查方向 |
| --- | --- |
| 教室端连不上 | 先在教室电脑上浏览器打开 `https://你的域名/health`，能返回 JSON 说明网络通，问题在客户端配置；打不开则是学校网络限制 |
| 教室端反复掉线重连 | 网关在掐长连接。调小 `HEARTBEAT_INTERVAL_MS`（如 15000）再观察 |
| 教师端在线状态不刷新 | SSE 被反向代理缓冲了。服务端已设 `X-Accel-Buffering: no`，检查 nginx 版本是否支持该头 |
| 发布成功但教室端没反应 | 看 `/api/classes` 返回的 `online` 是否为 0，为 0 说明设备根本没连上 |
| 重启后全部要重新登录 | `TOKEN_SECRET` 没设置，用的随机密钥 |
| 页面打开是空白 | 检查 `WEB_ROOT` 是否为 `/app/web`，以及镜像是否为最新多阶段构建版本 |
