## 1. 总体拓扑

```
┌────────────────────┐          ┌────────────────────┐
│  教师端 Web / H5    │  HTTPS   │                    │
│  （响应式，一套代码）│─────────▶│                    │
│  发布 / 管理 / 绑定 │◀── SSE ──│                    │
└────────────────────┘  状态推送 │    云服务端         │
                                 │  API + 推送 + TTS   │
┌────────────────────┐          │                    │
│  教室端 Electron    │  WSS     │                    │
│  全屏展示 + 语音     │◀────────▶│                    │
│  （无账号，凭码绑定）│  长连接   │                    │
└────────────────────┘          └────────────────────┘
```

三端职责：

| 端 | 职责 | 不做什么 |
| --- | --- | --- |
| 教师端 Web/H5 | 登录、班级管理、发布通知、生成绑定码、查看在线状态与发布记录 | 不直连教室端 |
| 教室端 Electron | 接收通知、全屏展示、语音播报、回执 ACK、上报心跳 | 不登录、不发布、无输入 |
| 云服务端 | 鉴权、班级/设备管理、消息投递与重推、在线状态维护 | — |

## 2. 服务端地址可配置

教室端**不硬编码**服务端地址。优先级从高到低：

1. **应用内设置页**（主路径）—— 客户端首启即进入配置向导：服务器地址 + 绑定码两个输入框；绑定后可从托盘菜单再次进入
2. **安装目录下的 `config.txt`**（批量部署 / IT 老师用）—— 纯文本，记事本可直接改
3. 内置默认值

### config.txt 格式

**不用 JSON。** 手改 JSON 有两个必踩的坑：中文输入法会打出全角引号 `""`，以及末尾多一个逗号——两者都会让解析直接失败，而老师看不懂报错。

改用最宽容的 `键=值`：

```ini
# 班级通知屏 配置文件
# 用记事本打开，改等号后面的内容，保存即可。

服务器地址 = https://notice.example.com
```

解析器要求：

- 忽略 `#` 开头的注释行与空行
- 等号前后的空格全部忽略
- 同时接受中文键名和英文键名（`服务器地址` / `serverUrl`）
- 容忍全角等号 `＝` 和全角引号
- **编码兼容 UTF-8（含 BOM）与 GBK**：Win7 自带记事本默认存 ANSI（即 GBK），Win10 之后才默认 UTF-8。只按 UTF-8 读会在老机器上直接乱码

### 文件位置的坑

如果客户端装进 `C:\Program Files\`，老师用记事本改完**保存不了**（需要管理员权限），而记事本给的提示很不友好。两个办法，建议都做：

1. Electron NSIS 打包走 **per-user 安装**（装到 `%LOCALAPPDATA%`），配置文件天然可写
2. 在开始菜单和托盘菜单里放一个「打开配置文件」入口，直接用记事本打开正确的那个文件，省得老师自己找路径

## 3. 通信设计

### 教师端 → 云端

普通 HTTPS REST。发布通知是一次 POST，同步返回受理结果（不等教室端 ACK）。

在线状态和送达回执通过 **SSE** 推给教师端。选 SSE 不选 WebSocket 的理由：教师端只需要单向下行，SSE 基于普通 HTTP，浏览器自带断线重连，H5 上更省心。

### 云端 → 教室端

**WSS 长连接（443）**，教室端主动出站建立。

- 心跳：服务端每 25s 下发 `ping`，客户端收到任何帧都刷新活跃时间；服务端 60s 未收到任何帧判定离线
- 重连：指数退避 1s → 2s → 4s … 封顶 30s，叠加 ±20% 随机抖动，避免全校设备同时重连打垮服务端

### 消息帧

```jsonc
// 云端 → 教室端：下发通知
{
  "type": "notice",
  "id": 12,
  "content": "请全班同学马上到操场集合。",
  "publisher": "王老师",
  "publishedAt": 1757222400,
  "displaySeconds": 60,
  "speakTimes": 2,
  "expireAt": 1757222700   // TTL，教室端本地判断，过期丢弃
}

// 教室端 → 云端：回执
{ "type": "ack", "id": 12, "status": "displayed" }

// 双向心跳
{ "type": "ping", "ts": 1757222400000 }  // 服务端发
{ "type": "pong", "ts": 1757222400000 }  // 客户端回
```

## 4. 关键流程

### 4.1 教室端绑定

1. 教师在 Web 端选中班级，点"生成"，云端返回 6 位绑定码 + 过期时间（30 分钟）
2. 教室电脑上打开客户端，输入服务器地址与绑定码
3. 云端校验后返回长期 `deviceToken` 与班级信息，绑定码作废
4. 此后教室端一律用 `deviceToken` 认证，不再依赖绑定码

**限流**：同一 IP 10 分钟内失败 10 次，绑定接口返回 429。

**同名设备复用**：同一班级内同名设备重新绑定时更新 token，不堆积多条记录，方便换机器。

### 4.2 发布通知

1. 教师端 POST `/api/notices`，云端落库，状态 `pending`
2. 云端查该班级在线设备，沿 WebSocket 逐台下发
3. 教室端展示并播报后回 `ack`，云端置为 `delivered`，经 SSE `notice_ack` 事件通知教师端
4. 未 ACK 的在 TTL（默认 5 分钟）内重推，超时置为 `expired`

### 4.3 离线与 TTL

设备离线时的通知默认不立即补发。理由：这类通知强时效（"马上到操场集合"），学生放学后再播是负价值。TTL 内设备上线则补投一次（调 `deliverPending`），超出即作废。

## 5. Web 端路由

教师端 Web 使用 React + react-router-dom v7，分两个页面：

| 路径 | 组件 | 说明 |
| --- | --- | --- |
| `/` | `LandingPage` | 落地页：产品介绍、卖点、演示，支持直接登录 |
| `/console/*` | `ConsolePage` | 工作台：班级管理、发布通知、绑定教室等完整功能 |
| 其他 | 重定向到 `/` | SPA 回退 |

登录逻辑：
- 未登录访问 `/console` → 在 `ConsolePage` 内部检测并跳转回 `/`（显示登录弹窗）
- 落地页登录成功 → `navigate('/console', { replace: true })`
- 已登录直接访问 `/` → 自动重定向到 `/console`

服务端已内建 SPA 回退（`setNotFoundHandler` 中对非 `/api`、非 `/ws` 路径统一返回 `index.html`），**无需在 nginx 额外配置 `try_files`**。

## 6. 数据模型

| 表 | 关键字段 |
| --- | --- |
| `teacher` | id, username, password, display_name, disabled, created_at |
| `class` | id, name, created_at |
| `teacher_class` | teacher_id, class_id, role（owner/assistant） |
| `device` | id, class_id, token_hash, name, last_seen_at, created_at |
| `bind_code` | code, class_id, created_by, expire_at, used_at |
| `notice` | id, class_id, publisher_id, content, display_seconds, speak_times, expire_at, status, created_at |
| `notice_delivery` | notice_id, device_id, status, acked_at |
| `setting` | key, value（invite_code / reg_open 等） |

`teacher_class` 独立成表，支撑"兼任"场景——一个班级可被多个老师发布通知。

## 7. 技术选型（已定）

| 层 | 选型 | 备注 |
| --- | --- | --- |
| 教师端 | React 19 + Vite + TypeScript | 移动优先响应式，视觉走暖黄风格（见 `设计规范.md`）。组件库倾向不引入，按设计 token 自己写 |
| 路由 | react-router-dom v7（BrowserRouter） | SPA，`/` 落地页 + `/console/*` 工作台 |
| 服务端 | Node.js + Fastify（ESM，无 TS） | 全栈 JS。依赖仅 fastify / ws / better-sqlite3，内建静态文件服务，省掉 nginx 容器 |
| 数据库 | SQLite（better-sqlite3） | 写入量极低，单文件零运维，省下一个容器和 100+MB 内存 |
| 在线状态 | 进程内存（Map） | 不引入 Redis。重启后教室端自动重连恢复 |
| 教室端 | Electron 22.3.x | 兼容 Win7 32 位的上限版本 |
| 语音播报 | 教室端本地合成（speechSynthesis → Windows SAPI） | 省服务器算力和带宽，断网仍能播 |
| 构建 / CI | electron-builder + GitHub Actions | Windows 在 windows-latest 构建，macOS 在 macos-latest 构建（不可跨平台） |

## 9. 轻量化取舍（2026-09-07）

VPS 配置有限，以下三处从原设计降级，都是"省资源且不损功能"的选择：

| 原设计 | 改为 | 省下什么 |
| --- | --- | --- |
| PostgreSQL 容器 | SQLite 单文件 | 一个容器、100~150 MB 内存、一份备份运维 |
| 云端 TTS 合成 mp3 | 教室端本地语音合成 | 服务器算力、音频带宽、第三方 TTS 费用；且断网仍能播报 |
| nginx 容器托管前端 | 服务端内建静态文件服务 | 一个容器 |

实测服务端空载常驻内存约 76 MB，镜像约 180 MB。
