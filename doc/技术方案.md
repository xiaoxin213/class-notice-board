## 1. 总体拓扑

```
┌────────────────────┐          ┌────────────────────┐
│  教师端 Web / H5    │  HTTPS   │                    │
│  （响应式，一套代码）│─────────▶│                    │
│  发布 / 管理 / 绑定 │◀── SSE ──│                    │
└────────────────────┘  状态推送 │    云服务端         │
                                 │  API + 推送 + TTS   │
┌────────────────────┐          │                    │
│  教室端 Electron    │  WSS     │                    │
│  全屏展示 + 语音     │◀────────▶│                    │
│  （无账号，凭码绑定）│  长连接   │                    │
└────────────────────┘          └────────────────────┘
```

三端职责：

| 端 | 职责 | 不做什么 |
| --- | --- | --- |
| 教师端 Web/H5 | 登录、班级管理、发布通知、生成绑定码、查看在线状态与发布记录 | 不直连教室端 |
| 教室端 Electron | 接收通知、全屏展示、语音播报、回执 ACK、上报心跳 | 不登录、不发布、无输入 |
| 云服务端 | 鉴权、班级/设备管理、消息投递与重推、TTS 合成、在线状态维护 | — |

## 2. 服务端地址可配置

教室端**不硬编码**服务端地址。优先级从高到低：

1. **应用内设置页**（主路径）—— 客户端首启即进入配置向导：服务器地址 + 绑定码两个输入框；绑定后可从托盘菜单再次进入
2. **安装目录下的 `config.txt`**（批量部署 / IT 老师用）—— 纯文本，记事本可直接改
3. 内置默认值

> 原方案里的命令行参数降级为 v1 不做。老师不会用命令行，IT 批量装机改一个文本文件也够了，等真有静默部署需求再补。

### config.txt 格式

**不用 JSON。** 手改 JSON 有两个必踩的坑：中文输入法会打出全角引号 `“”`，以及末尾多一个逗号——两者都会让解析直接失败，而老师看不懂报错。

改用最宽容的 `键=值`：

```ini
# 班级通知屏 配置文件
# 用记事本打开，改等号后面的内容，保存即可。

服务器地址 = https://notice.example.com
```

解析器要求：

- 忽略 `#` 开头的注释行与空行
- 等号前后的空格全部忽略
- 同时接受中文键名和英文键名（`服务器地址` / `serverUrl`）
- 容忍全角等号 `＝` 和全角引号
- **编码兼容 UTF-8（含 BOM）与 GBK**：Win7 自带记事本默认存 ANSI（即 GBK），Win10 之后才默认 UTF-8。只按 UTF-8 读会在老机器上直接乱码

### 文件位置的坑

如果客户端装进 `C:\Program Files\`，老师用记事本改完**保存不了**（需要管理员权限），而记事本给的提示很不友好。两个办法，建议都做：

1. Electron NSIS 打包走 **per-user 安装**（装到 `%LOCALAPPDATA%`），配置文件天然可写
2. 在开始菜单和托盘菜单里放一个「打开配置文件」入口，直接用记事本打开正确的那个文件，省得老师自己找路径

## 3. 通信设计

### 教师端 → 云端

普通 HTTPS REST。发布通知是一次 POST，同步返回受理结果（不等教室端 ACK）。

在线状态和送达回执通过 **SSE** 推给教师端。选 SSE 不选 WebSocket 的理由：教师端只需要单向下行，SSE 基于普通 HTTP，浏览器自带断线重连，H5 上更省心。

### 云端 → 教室端

**WSS 长连接（443）**，教室端主动出站建立。

- 心跳：客户端每 25s 发 `ping`，服务端回 `pong`；服务端 60s 未收到心跳判定离线
- 重连：指数退避 1s → 2s → 4s … 封顶 30s，叠加 ±20% 随机抖动，避免全校设备同时重连打垮服务端
- 降级：WSS 连续失败 N 次后降级为 HTTPS 长轮询（2~3s 一次）。SSE 作为中间档暂不做，先留接口位置

### 消息帧草案

```jsonc
// 云端 → 教室端：下发通知
{
  "type": "notice",
  "id": "ntc_xxx",              // 幂等键，教室端去重
  "content": "请全班同学马上到操场集合。",
  "publisher": "王老师",
  "publishedAt": 1757222400,
  "displaySeconds": 60,          // 大屏显示时间
  "speakTimes": 2,               // 语音播报次数
  "expireAt": 1757222700         // TTL，过期不再展示（语音由教室端本地合成）
}

// 教室端 → 云端：回执
{ "type": "ack", "id": "ntc_xxx", "status": "displayed" }

// 教室端 → 云端：心跳
{ "type": "ping", "ts": 1757222400 }
```

## 4. 关键流程

### 4.1 教室端绑定

1. 教师在 Web 端选中班级，点"生成"，云端返回 6 位绑定码 + 过期时间
2. 教室电脑上打开客户端，输入服务器地址与绑定码
3. 云端校验后返回长期 `deviceToken` 与班级信息，绑定码作废
4. 此后教室端一律用 `deviceToken` 认证，不再依赖绑定码

**限流**：6 位码空间仅 100 万，按 IP + 按码双维度限制尝试次数，连续失败锁定。

### 4.2 发布通知

1. 教师端 POST 发布，云端落库，状态 `pending`
2. 云端查该班级在线设备，沿已建立的 WSS 逐台下发
3. 教室端展示并播报后回 `ack`，云端置为 `delivered`，经 SSE 通知教师端 → UI 显示"教室端已收到通知"
4. 未 ACK 的按退避重推，直到 `expireAt` 到期置为 `expired`

### 4.3 离线与 TTL

设备离线时的通知**默认不补发**。理由：这类通知强时效（"马上到操场集合"），学生放学后再播是负价值。TTL 内设备恢复上线则补投一次，超出即作废。

## 5. 数据模型草案

| 表 | 关键字段 |
| --- | --- |
| `teacher` | id, username, password_hash, display_name, invite_code_used, created_at |
| `class` | id, name, owner_teacher_id, created_at |
| `teacher_class` | teacher_id, class_id, role（班主任/兼任） |
| `device` | id, class_id, device_token_hash, last_seen_at, status |
| `bind_code` | code, class_id, created_by, expire_at, used_at |
| `notice` | id, class_id, publisher_id, content, display_seconds, speak_times, audio_url, expire_at, status, created_at |
| `notice_delivery` | notice_id, device_id, status, acked_at |

`teacher_class` 独立成表，是为了支撑截图里的"兼任"标签——一个班级可以被多个老师发布。

## 6. 技术选型（已定）

| 层 | 候选 | 备注 |
| --- | --- | --- |
| 教师端 | React + Vite + TS，**移动优先**响应式 | 视觉走暖黄风格，见 `设计规范.md`。组件库倾向不引入，按设计 token 自己写 |
| 服务端 | **Node.js + Fastify**（ESM，暂不上 TS） | 全栈 JS。依赖只有 fastify / ws / better-sqlite3 三个，静态资源用自写的 30 行处理器托管，省掉 nginx 容器 |
| 数据库 | **SQLite**（better-sqlite3） | 改自 PostgreSQL：写入量极低，单文件零运维，省下一个容器和 100+MB 内存 |
| 在线状态 | 进程内存 | 不引入 Redis。重启后教室端自动重连恢复 |
| 教室端 | Electron 22.3.x | 兼容 Win7 32 位的上限版本 |
| 语音播报 | **教室端本地合成**（Chromium speechSynthesis → Windows SAPI） | 改自云端 TTS：省服务器算力、省带宽、省第三方费用，且断网也能播 |

## 7. 轻量化取舍（2026-09-07 修订）

VPS 配置有限，以下三处从原设计降级，都是"省资源且不损功能"的选择：

| 原设计 | 改为 | 省下什么 |
| --- | --- | --- |
| PostgreSQL 容器 | SQLite 单文件 | 一个容器、100~150 MB 内存、一份备份运维 |
| 云端 TTS 合成 mp3 | 教室端本地语音合成 | 服务器算力、音频带宽、第三方 TTS 费用；且断网仍能播报 |
| nginx 容器托管前端 | 服务端自行托管静态文件 | 一个容器 |

代价是：本地合成的音色由教室电脑的系统语音决定，各机器可能不一致，且 Win7 自带中文语音（Huihui）音质一般。真要统一音色，后续可以把云端 TTS 作为可选项加回来——协议里 `notice` 帧预留了这个扩展位。

实测服务端空载常驻内存约 76 MB，镜像约 150 MB。
